# Production Workflow

## Intake checklist
- [ ] Primary footage identified
- [ ] Script/transcript/reference script received
- [ ] Target platform and duration confirmed or defaulted
- [ ] Reference edits received (optional)
- [ ] Music/SFX rights understood
- [ ] Project folder created; source media preserved

## Story architecture
Use only the beats the story needs:
1. Hook: a question, contradiction, surprising fact, or vivid moment.
2. Context: minimum information needed to understand the premise.
3. Escalation: evidence, complication, contrast, or deeper question.
4. Payoff: answer, insight, reveal, or reframing.
5. Close: emotional or intellectual aftertaste.

Do not force every video into a rigid five-part structure.

## Edit decision process
1. Transcribe and identify selects.
2. Mark mistakes, false starts, repeated ideas, and silence.
3. Build a paper edit before assembling.
4. Approve material narrative changes.
5. Assemble A-roll for clarity.
6. Add cutaways only where they carry information.
7. Add captions and graphics.
8. Design sound and music.
9. Colour correct and finish.
10. Render, inspect, revise, and deliver.

## Timecode convention
Use HH:MM:SS.mmm for source in/out. Keep source timecode distinct from timeline timecode. If only approximate timecodes are available, label them approximate. Never invent frame-accurate values.

## EDL minimum fields
- Clip/source filename
- Source in/out
- Timeline in/out
- Spoken line/beat
- Action
- Reason
- Asset reference
- Approval status

## Revision protocol
- Keep a change log.
- Preserve approved decisions unless the user asks to change them.
- Make requested changes narrowly.
- Re-run relevant QC after every render.
